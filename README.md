# Smart-City-Infrastructure-and-Route-Planning
Assignment 3 — Smart City Infrastructure and Route Planning 
## Overview
This Java application models city districts as vertices and roads or service connections as weighted edges. It implements minimum spanning trees, directed-graph connectivity algorithms, and shortest paths.

Vertices are numbered from 0 to V - 1. The graph uses an adjacency list for neighbor access and an edge list for algorithms that process all edges. Undirected edges are stored in the edge list once and in both endpoint adjacency lists.

## Implementation
- Graph and Edge
Graph stores the number of vertices, whether the graph is directed, a list of edges, and an adjacency list. It validates vertex indices. Edge stores its source, destination, and integer weight.
Disjoint Set Union (DSU)
DSU supports find and union. Path compression makes nodes point more directly to their representative. Union by rank attaches the shallower tree below the deeper tree. Together, these optimizations make a sequence of DSU operations nearly constant amortized time: O(α(V)), where α is the inverse Ackermann function.
- Kruskal's Algorithm
Kruskal sorts edges by weight and considers them from smallest to largest. DSU prevents adding an edge that would create a cycle. The result reports selected edges, total weight, connectivity, and edge examinations. Time complexity is O(E log E), including sorting. Auxiliary space is O(V + E) for the copied/sorted edge list and DSU.
- Prim's Algorithm
Prim starts from vertex 0 and repeatedly selects the lowest-weight candidate edge that reaches an unvisited vertex. A priority queue manages candidates. It reports the MST weight and whether all vertices were reached. With an adjacency list and binary heap, the usual bound is O((V + E) log E); auxiliary space is O(V + E) for the queue and result.

Both MST algorithms require an undirected weighted graph. For a connected graph, Kruskal and Prim must return the same minimum total weight. If the graph is disconnected, the returned edges form a minimum spanning forest and connected is false. For a graph with one vertex, the MST is connected and has weight zero.
- Strongly Connected Components (Kosaraju)
Kosaraju's algorithm performs DFS to record finishing order, reverses every directed edge, and performs DFS in reverse finishing order on the reversed graph. Each second-pass DFS identifies one strongly connected component. Time complexity is O(V + E); space complexity is O(V + E) for the reverse graph, visited array, and traversal lists.
- Topological Ordering
The implementation uses Kahn's algorithm. It computes in-degrees, places zero-in-degree vertices in a queue, and removes them while reducing the in-degree of their outgoing neighbors. If all vertices are output, the graph is a DAG and the order is valid. If fewer than V vertices are output, a directed cycle exists and a complete topological order is impossible. Time complexity is O(V + E); space complexity is O(V).
- Dijkstra's Algorithm
Dijkstra uses a priority queue to repeatedly process the currently known closest vertex and relax its outgoing edges. It returns distances and predecessor links, allowing a shortest path to be reconstructed. Vertices that cannot be reached have distance Long.MAX_VALUE and an empty path. Negative weights are rejected.

Dijkstra is unsuitable for negative edge weights because a vertex finalized as the closest may later be reached by a lower-cost path through a negative edge. Its greedy assumption no longer holds. With an adjacency list and binary heap, the typical time complexity is O((V + E) log V), and auxiliary space is O(V + E).

## Experimental Setup
The benchmark uses three configurations from the assignment: (V, E) = (10, 30), (100, 500), and (1,000, 5,000). A fixed seed is used for each generated graph, so the input can be reproduced. Undirected MST graphs are connected by first generating a spanning tree and then adding distinct random edges. Weights are non-negative integers from 1 to 100.

Directed random graphs allow cycles for SCC experiments. DAGs are generated by allowing edges only from a lower-numbered vertex to a higher-numbered vertex, which prevents directed cycles. The benchmark runs each algorithm five times and measures elapsed time using System.nanoTime(). It reports the average time in nanoseconds. JVM warm-up, garbage collection, and machine load can affect small timings, so results should be interpreted as measurements from this environment rather than universal constants.

The operation counter is an algorithm-specific count, not a directly comparable count of identical machine instructions. Kruskal counts examined edges; Prim and Dijkstra count queue removals and examined adjacency edges. SCC and topological sorting timings are recorded, but their operation counts are not instrumented in this starter implementation.

## Comparison and Discussion
Kruskal sorts all edges, so sorting is its main cost. It is a natural choice when processing an edge list. Prim grows a tree from a starting vertex and uses a priority queue to select candidate edges. Both produce a minimum spanning tree on a connected undirected graph, but their observed running times depend on graph structure, implementation, JVM warm-up, and hardware.

SCC and topological ordering are linear in the number of vertices plus edges. A graph with more edges requires more adjacency entries to inspect. Topological ordering succeeds for DAGs and reports failure when a directed cycle prevents a complete ordering.

Dijkstra's priority queue supports efficient shortest-path search when all weights are non-negative. As graph size increases, more vertices and edges may need processing. Its results are distances from one source, not an all-pairs shortest-path solution.
## Conclusion
The application demonstrates several graph algorithms for smart-city planning. Kruskal and Prim minimize the total cost of connecting districts; DSU supports cycle prevention in Kruskal; Kosaraju identifies strongly connected groups; topological ordering checks dependency order and detects cycles; and Dijkstra finds shortest paths from one source.
